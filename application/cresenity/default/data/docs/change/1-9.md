# Change Log 1.9

- CF
  - Fix `CElement_Component_DataTable`'s export traits (`ExportTrait.php` and `Legacy/ExportTrait.php`) reading a `$footer_field`/`$this->footer_field` property that doesn't exist — the real property (from `CElement_Component_DataTable_Trait_FooterTrait`) is `$footerFields`, an array of `CElement_Component_DataTable_FooterField` objects. Any DataTable export with the footer enabled hit a null/undefined access; now reads via `getLabel()`/`getValue()`/`getAlign()`/`getLabelColSpan()`
  - Investigated a reported `CElement_FormInput_EditorJs_Tool_ImageTool` fatal-crash report — not reproducible against current code; `ImageTool` never reads the `toolSettings.image.services` key the report described (only `EmbedTool` reads a `.services` key, from `toolSettings.embed.services`, which does exist). No fix needed
  - **Rollback:** removed the per-app "public docroot" feature (`CF::publicPath()`, root `DOCROOT/public` folder, `CHTTP_FileServeDriver`, `asset:install` console command). Apps are always served through the shared front controller now; Vite builds and framework/theme assets resolve under each app's `default/media` directory instead of a dedicated public folder per app. `CF::isIndexInApp()` is kept (still used by `CF::appCode()` for CLI/app-identity resolution) but no longer implies a separate public docroot
  - `.htaccess` hardened: block `logs/`, `.env`, `.sql`, `.key`/`.pem`, `.DS_Store`, `.php-cs-fixer.cache`, `.phpunit.result.cache`, and `TODO.md` from direct web access — found `application/aidnity/.env` and a real OAuth private key (`oauth-private.key`) were both directly web-reachable
  - New `tests/Translation/` suite (108 tests) covering `CTranslation_Translator` fallback/placeholder behavior and real `system/i18n/` data integrity; fixed a dead `en_US/filemanager.php` stub (evaluated to `int(1)`, no `return`) and a stale `%s`-style placeholder in `id_ID/core.php`'s `driver_not_found`. Removed `system/i18n/en/` (byte-identical to `en_US/`, only real consumer was `shopnest`'s bare `'en'` locale, fixed to `en_US`)
- CElement
  - `CElement_FormInput_Text` converted to cres.js (`control:Text`); removed dead `$action`/`add_action()`/`buttonPosition` API and the no-op `$this->validation->validationClass()` call (also removed from remaining FormInput classes)
  - `CElement_FormInput_FileAjax` now extends `CElement_FormInput_File` (was a sibling); `acceptFile` moved to the shared parent and validated client-side. Both converted to cres.js (`control:File`, `control:FileAjax`)
  - Added translated error messages for accept-file/upload validation (`element/file.errorMessageAcceptFileNotAllowed`, new `element/upload.php` i18n group) surfaced via `cres-config` instead of hardcoded English strings in JS and `CAjax` upload traits
