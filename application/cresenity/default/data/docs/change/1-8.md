# Change Log 1.8


- CF
  - Adding support for PHP 8.4
  - Fix missing `cf` marker file required by `phpcf` CLI to locate the framework root — without it, `phpcf`'s upward directory search failed silently and it required() an absolute path from filesystem root instead of `system/core/Bootstrap.php`
  - Fix a shadowed loop variable in `cstr::is()` and `cstr::isMatch()` (the `foreach` reused the `$pattern` parameter name)
- CRouting
  - **Security:** `CController::callAction` now validates method visibility — only `public` methods can be called via URL. Protected and private methods return 404
  - **Security:** Magic methods (`__construct`, `__destruct`, `__call`, etc.) are blocked from being routed directly
  - **Security:** Internal controller methods (`callAction`, `middleware`, `getMiddleware`) are blocked from URL access via a configurable blacklist (`CController::getBlockedMethods`)
  - **Security:** `CRouting_RouteFinder` now rejects methods inherited from `CController` base class from being auto-discovered as routes
  - **Feature:** Auto-discovered routes now support HTTP verb prefixes on controller methods. Prefix a method name with the HTTP verb to restrict which methods it accepts:
    - `getDetail($id)` — responds to GET and HEAD only
    - `postStore()` — responds to POST only
    - `putUpdate($id)` — responds to PUT only
    - `deleteRemove($id)` — responds to DELETE only
    - `anyProcess()` — responds to all HTTP verbs (explicit)
    - `index()` — no prefix, responds to all HTTP verbs (backward compatible)
  - Requesting a URL with the wrong HTTP verb now returns `405 Method Not Allowed` with a proper `Allow` header, instead of 404
  - Controllers using `__call` magic method as a catch-all continue to work correctly
- CDatabase

  - Fix PostgresBuilder caller to pass `$schema` and `$table` arguments

  - Fix `ModelDataProvider` correlating BelongsToMany sort subqueries — sorting a data provider grid by a column through a plain `belongsToMany` relation (not just `belongsTo`) previously caused "Cardinality violation: Subquery returns more than 1 row"

  - Add missing PHPDoc across `CDatabase_Connection` compat methods
  - Fix `transactionsManager` property typo in `handleRollBackException` that silently skipped calling the transaction manager's rollback on lost-connection errors

Prompts for the app's class prefix (used to generate `{PREFIX}.php`/`{PREFIX}Model.php`/`{PREFIX}Controller.php`/`{PREFIX}Utils.php`) and, optionally, an admin preset, then scaffolds config, media, theme, libraries, views, controllers, nav, bootstrap, and `env.php`/`env.example.php`. Along the way, fixes several bugs inherited from `app:create`: the `--title` option was accepted but never actually written to `config/app.php`; a dead `CConfig::instance('app')->refresh()` call (the `refresh()` method was removed from the framework in 2024 when config loading moved to `CFConfig::bootstrap()`) is replaced with a working `CFConfig::loadConfiguration()` reload; `bootstrap.php` is no longer unconditionally overwritten on a re-run, so a customized bootstrap survives running the wizard again (e.g. to add an admin preset later); no longer auto-opens a browser via `devsuite:open`, just prints the app URL
  - `system/stubs/config/app.stub`: `environment` and `key` now read from `c::env('ENVIRONMENT', CBase::ENVIRONMENT_DEVELOPMENT)`/`c::env('APP_KEY')` instead of being hardcoded; new `system/stubs/env/env.stub` and `env.example.stub` back these for freshly scaffolded apps
  - Fix `nav.stub`/`bootstrap.stub` using uppercase `OR` instead of lowercase `or` in `defined('SYSPATH') or die(...)` (phpcs violation)
  - `bootstrap.stub` now calls `c::manager()->theme()->setTheme()` instead of the deprecated `CApp::setTheme()`
  - Fix inaccurate `@return OutputInterface` docblock on `CConsole_Prompt::output()` (actual type is always `CConsole_Prompt_Output_ConsoleOutput` or its `BufferedConsoleOutput` subclass) causing a false-positive "undefined method" diagnostic on the guarded `method_exists()` calls in `CConsole_Prompt::capturePreviousNewLines()`/`writeDirectly()`

  - Retry a resource download (with a short delay) before throwing `UnreachableUrl` — DigitalOcean Spaces redirect URLs can be briefly unreachable right after upload
- CDaemon
  - Extract `CDaemon_RunnerAbstract` base class — eliminates code duplication across `CDaemon_Runner`, `CDaemon_Supervisor_Runner`, `CDaemon_Supervisor_WorkerRunner`
  - Move network server classes from `CDaemon/Worker/` to `CDaemon/Server/` — separates network server (TCP/WebSocket) from parallel task (fork/IPC) concerns. Old class names remain as backward-compatible wrappers
  - New `CDaemon_Server` facade, `CDaemon_Server_EventLoop`, `CDaemon_Server_Constant` — replaces all Workerman references with CF-native implementations
  - Move `CDaemon_WorkerProcess` to `CDaemon_Supervisor_WorkerProcess` (old name still works)
  - Add configurable `daemon.php_binary` config — allows overriding the PHP binary path used by daemon runners
  - Fix critical bug: `parentPid` assignment (`==` vs `=`) in `ServiceAbstract`
  - Fix PHP 8 compatibility: `is_resource()` checks for SysV handles, `shm_detach` null guard, `callCount` type error
  - Fix `Core_*` PHPDoc references — replaced with CF class names
  - Add `getCallCount()`/`setCallCount()` to `MediatorAbstract`, `checkEnvironment()` to `ViaInterface`
  - Self-terminate a `CDaemon_BackgroundProcess` worker when its supervisor dies, instead of leaking orphaned workers indefinitely after a supervisor restart
  - Swallow console-output write failures (e.g. a broken pipe on a detached process) instead of crashing the whole queue worker loop — PHP 8's stricter warning handling surfaced this more often than PHP 7.4
  - Guard a vendored `React\Promise` `method_exists()` call against PHP 8.4's stricter `TypeError` on non-object arguments — a Redis message resolving to an array could crash the WebSocket daemon
- CDevSuite
  - Remove `@author Hery` PHPDoc tags across the library and its `CConsole` `devsuite:*` command wrappers
  - **Fix `devsuite:secure` on Linux — SSL was effectively non-functional:**
    - The self-signed root CA generated by `createCa()` was never trusted anywhere (no system trust store, no NSS). Added `CDevSuite_Linux_Site::trustCa()`, auto-detecting `update-ca-certificates` (Debian/Ubuntu), `update-ca-trust` (Fedora/RHEL), or `trust` (Arch) to install it
    - Per-site certificate trust into Firefox's NSS database used a `*.default` profile glob that only matches legacy profile names — modern Firefox uses `*.default-release`/`*.default-esr`/custom names, so trust silently failed on any current install. Replaced with a loop over every profile directory (also covers the Snap Firefox path)
    - `openssl`/`certutil` calls had no error handler, so failures were silently swallowed and `devsuite:secure` reported success regardless. Added warnings surfaced via `CDevSuite::warning()`
    - `CDevSuite_Linux_Site::getCertificates()` hardcoded a 4-character TLD assumption (`substr($cert, 0, -9)`), corrupting the "secured" column and `unsecureAll()` for any non-default TLD (e.g. `devsuite:tld local`). Removed the override in favor of the already-generic base implementation
    - Added an `openssl`/`certutil` dependency check to `CDevSuite_LinuxRequirements::check()`, run during `devsuite:install`, so missing packages are surfaced up front instead of failing silently later
  - **Fix `devsuite:tld` on Linux and Mac:** `CDevSuite_Command_TldCommand` called `CDevSuite::acrylic()`, which is unconditionally the Windows-only Acrylic class (`CDevSuite` pulls in `WindowsTrait` regardless of OS), on every platform. Changing the TLD updated nginx/cert config but never told dnsmasq about the new domain, so the new TLD silently failed to resolve. Now dispatches to `CDevSuite::dnsMasq()->updateTld()` on non-Windows. Unified the previously-diverging method name (`Linux_DnsMasq::updateDomain()` → `updateTld()`, matching Mac) and declared it abstract on `CDevSuite_DnsMasq`
  - Fix the standalone Linux `devsuite` bash CLI (`system/data/devsuite/scripts/linux/bootstrap.sh`): a bash syntax error (`ISSUDO = $SUDO`, missing `then`) made the script fail to parse entirely; `CDevSuite_Linux_System::symlinkToUsersBin()` was a commented-out no-op so the `devsuite` binary was never installed to `PATH`; legacy `~/.devsuite/` paths (pre-dating the `~/.config/devsuite/` convention) in `bootstrap.sh` and `update.sh`; final command dispatch pointed at a nonexistent `cli/devsuite.php` — now proxies to `phpcf devsuite:<command>`, the actual working entry point (`CConsole_Command_DevSuite_*`). Also removed a dead `composer global update "cpriego/valet-linux"` branch left over from the upstream fork this library was based on
  - Declare `installDevSuiteDns()` abstract on `CDevSuite_ServiceManager` and `nmRestart()` abstract on `CDevSuite_PackageManager` (both were only declared on concrete per-distro subclasses), and add full PHPDoc to both abstract classes
- CPagination
  - Add `#[\ReturnTypeWillChange]` attribute to `count()`, `getIterator()`, `offsetExists()`, `offsetGet()`, `offsetSet()`, `offsetUnset()`, `jsonSerialize()` for PHP 8.1+ compatibility
